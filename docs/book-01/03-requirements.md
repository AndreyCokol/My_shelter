# My Shelter — PRD / SRS (песочница по мотивам произведения)

**Версия:** G0 CANDIDATE 2.0 · **Решения владельца:** 2026-11-05 (10 продуктовых решений + A0) · **Состояние:** документация, игровой код ещё не создан. Главные ссылки: [геймдизайн песочницы](09-sandbox-gameplay-design.md), [сюжетные задания](02-story.md), [контракт](05-integration-contracts.md), [G0](08-g0-decision-record.md).

## 1. Цель и границы

**Продукт:** локальная однопользовательская 2D pixel-art песочница с видом сверху, боем в реальном времени и необязательными сюжетными заданиями; PC Windows x64, Godot 4.x + GDScript. **Вдохновлена** книгой 1 «Картошка есть? А если найду?», не является её линейной экранизацией. Книжные числа [К] — референсы; правила [П] и баланс конфигурируются отдельно.

**Обязательный P0-цикл:** исследовать небольшую территорию → рисковать и добывать ресурсы → переносить/хранить → выращивать/снабжать убежище → повышать прогресс/принимать жителей → самостоятельно выбирать следующую деятельность. Q01–Q02 — короткий onboarding/разблокировка Системы; дальнейшие Q03–Q07 могут сопровождать процесс, но не блокируют обычные хозяйственные действия.

**Первый играбельный MVP:** законченный вертикальный срез **15–35 минут активной игры** (гипотеза для UX проверки), с сохранением/загрузкой и возможностью продолжать свободную игру после обучающей цепочки. **Только личный закрытый прототип:** нет требования публичного релиза, загрузки в магазин, маркетинга, подключения к серверу.

**Вне P0:** весь лагерь Лувра и рынок, постоянный голод/работа жителей, полная система строительства и обороны, массовая эвакуация, множество районов, сотни NPC. **Весь пространственный осколок** (карта, инцидент, присоединитель и квесты) — `LATER`, **вне текущей кампании**, даже если он встречается в книге 1.

## 2. Приоритеты и статусы

- **P0:** без функции не работает первый завершённый цикл песочницы (G4).
- **P1:** развитие колонии и мира после первой работоспособной версии.
- **P2:** расширенное содержание/качество предметов и дополнительные сюжетные направления.
- **LATER:** полностью отложенный контент, без обязательства поставки и без зависимости G0–G5.
- **G0 CANDIDATE:** документ подготовлен, но ещё не утверждён владельцем по SHA; не выдавать за функционирующую реализацию.

## 3. Функциональные требования

| ID | P | Требование | Критерий проверки |
|---|---|---|---|
| FR-01 | P0 | Новая игра, меню, пауза и возврат | Время игры заморожено на паузе, UI работает; новая игра начинается из начального состояния |
| FR-02 | P0 | Управление 2D персонажем | Клавиатура/мышь, камера, столкновения, взаимодействие; ввод не проходит сквозь UI |
| FR-03 | P0 | Реальный бой | Движение, атака, **уклонение**, системное оружие, урон и смерть врага; начальная награда однократна |
| FR-04 | P0 | Характеристики и XP героя | Здоровье, опыт и уровень различимы, сохраняются; ошибочные/повторные начисления исключены |
| FR-05 | P0 | Пространственное убежище и переход | Сцена убежища и место возврата в городской мир сохраняются после загрузки |
| FR-06 | P0 | Базовое убежище | Видимая граница, палатка, источник воды, поле и доступ к хранению |
| FR-07 | P0 | Системные панели | Почта/посылки, магазин, прогрессия и статус убежища показаны на русском через UI A5 |
| FR-08 | P0 | Одноразовые посылки и системные покупки | Повтор не создаёт ресурс; отрицательного баланса нет, отказ отображается |
| FR-09 | P0 | Транзакционный инвентарь | Перенос, стеки/контейнеры/вместимость без потерь и дублирования, с проверкой происхождения |
| FR-10 | P0 | Разделение прогрессий | XP героя и убежища независимы; впервые обнаруженный тип предмета регистрируется один раз |
| FR-11 | P0 | Картофель и игровое время | Семена→поле→вода→созревание→сбор/порча; **естественное время и отдых** через один GameClock; числа из конфигурации, а не hardcode |
| FR-12 | P0 | Склады и пища | Продукты занимают место, хранятся и сохраняются; допускается резерв еды |

| FR-13 | P0 | Добровольные соглашения и первые жители | После явного согласия и удовлетворения FR-12a NPC уникально заселяется; согласие сохраняется при `AWAITING_SUPPLIES` |
| FR-14 | P0 | Квесты Q01–Q07 | Q01–Q02 — короткие разблокировки/обучение; Q03–Q07 необязательны для базовой симуляции, награды однократны |
| FR-15 | P0 | Сохранение/загрузка | Все игровые системы, таймеры, положения, резервы и квитанции восстанавливаются после перезапуска; ошибки файлов обрабатываются |
| FR-16a | P0 | Минимальная контактная зона | Доступ к встрече первых NPC; полный лагерь/торговля не требуются |
| FR-16b | P1 | Полный Лувр и торговля | Дополнительные диалоги, услуги, обмен и районы |
| FR-17 | P1 | Расширенное строительство | Предпросмотр, стоимость, ограничения размещения, сохранение построек |
| FR-18 | P1 | Труд, жильё и регулярное питание жителей | Расчёт один раз на игровом времени; P0 хранит только согласие и `job_id`, без симуляции потребления |
| FR-19 | P1 | Оборона и разновидности врагов | Вызовы обороны и дополнительные типы заражённых с проверяемым результатом |
| FR-20 | P1 | Расширение убежища/товаров | Новые условия открытия и балансовые правила без дублирования P0 |
| FR-21 | P0 | Квест «Новые лица» | Однократное завершение после заселения, допускает откладывание без блокировки песочницы |
| FR-22 | P2/OPTIONAL | Сюжетная массовая эвакуация | Если будет утверждена, агрегированные жители и условие/таймер из отдельного конфига, не обязательный финал |
| FR-23 | P2/OPTIONAL | Групповое переселение | Уникальный учёт групп; 1000 NPC не становятся 1000 физических Godot узлов |
| FR-24 | P2/OPTIONAL | Предупреждение о будущей угрозе | Сюжетный мотив только при отдельном согласовании; продолжение свободной игры возможно |
| FR-25 | LATER | Пространственный осколок | **Исключён** из MVP и всей текущей кампании, нет обязательных зависимостей и не создаются P0/P1 задачи |
| FR-26 | P2 | Расширенный лут | Качества предметов, дополнительные выпадения, оборудование |
| FR-27 | P1 | Дополнительные NPC/контракты/задания | Возможность самостоятельного выбора действий, отсутствие принуждения |
| FR-28 | P0 | Свобода песочницы | После Q01/Q02 можно минимум два содержательных цикла: ферма/хранение и вылазка/добыча, **без** активного Q03–Q07 |
| FR-29 | P0 | Продолжение после завершения демо-маршрута | Сохранение, загрузка, повторяемые занятия и свободное исследование; нет обязательного экрана «Конец первой книги» |
| FR-30 | P0 | Защита от безвыходного состояния при потере стартовых ресурсов | После расхода/потери начальных семян игрок может **повторно** добыть обычные семена через доступный ресурсный узел вне сюжетной цепочки; cooldown и выдача защищены от дублей |
| FR-31 | P0 | Восстановление после поражения в бою | В закрытом MVP нет необратимого permadeath: после смерти игрок может продолжить с последней безопасной точки, без повторной уникальной награды и повреждения сохранения |

## 4. Нефункциональные требования

| ID | Тема | Проверяемое условие |
|---|---|---|
| NFR-01 | Движок | **Godot 4.7.2-stable** стандартная (GDScript) — выбранный технический baseline; **реальный headless/GUI и Windows export ещё не проверены**, их проверяет A1 в G1a |
| NFR-02 | Локальная игра | Windows 10/11 x64; не нужны аккаунты, сервер, сетевой доступ или телеметрия |
| NFR-03 | Визуальный стандарт | 2D top-down pixel art, nearest-neighbor; 32×32 tile — рабочая гипотеза A5, подтверждение скриншотом/прототипом, UI Controls масштабируются отдельно |
| NFR-04 | Производительность | Цель 60 FPS на тестовом ПК в MVP, измерять Godot Profiler; до запуска `NOT_MEASURED` |
| NFR-05 | Надёжность | Нет потерь данных, двойных наград и скрытых ошибок загрузки; целостность на отказах |
| NFR-06 | Инварианты | Нет отрицательного остатка, повторного начисления, дублирования жителей/предметов и расхождения источников состояния |
| NFR-07 | Версионирование | `schema_version`, управление совместимостью и безопасное отклонение неизвестной схемы |
| NFR-08 | Русский язык | Русский UI, строки отделены от логики и доступны для последующей локализации |
| NFR-09 | Управление | InputMap для движения, взаимодействия, атаки, уклонения, паузы и UI; читаемость в уменьшенном окне |
| NFR-10 | Тестируемость | Unit/интеграционные/E2E и негативные сценарии; отчёт PASS/FAIL/NOT_RUN с воспроизводимыми командами |
| NFR-11 | Лицензии | Личный закрытый прототип; не публиковать защищённые тексты/ассеты, до распространения отдельно разобраться с правами адаптации |
| NFR-12 | Редакторская политика | Темы книги существенно переработаны для широкой аудитории; добровольные договоры, без сексуального насилия/эксплуатации/графической жестокости |
| NFR-13 | Время | Только один `GameClock`; `grow_minutes`, `spoil_minutes`, `minutes_per_real_second` — versioned `game_balance` |
| NFR-14 | Независимое ревью | Рискованные PR UI A5 проверяет A0 или другой reviewer; A0 сверяет FR→UI→состояние→сейв→тест без авторства чужого кода |

## 5. Минимальный сценарий приёмки

- E2E-01 — начало, система, первое оружие, победа и награда;
- E2E-02 — посадка, оба режима ожидания, сбор, хранение и пограничная порча по активному конфигу;
- E2E-03 — две независимые XP и недублирование;
- E2E-04 — согласие первых NPC, проверка переменного баланса еды, переселение, уникальность и квест;
- E2E-05 — полный restart/save/load, включая повреждённый основной save;
- E2E-07 — **свобода песочницы после onboarding без Q03–Q07**;
- E2E-08 — UI/ввод/пауза и повторное открытие окон без накопления подписок.

Подробные фикстуры, негативные сценарии и владельцы — [матрица](10-qa-acceptance-matrix.md). Проводятся также CT-27/28: возобновляемые ресурсы и восстановление после поражения. A5 ведёт функциональное тестирование, A0 выполняет независимую вертикальную сверку. Весь прогон **NOT_RUN**, пока игры нет.

## 6. Роли и принципы интеграции

A1 — общий state, инвентарь, экономика, прогрессия, GameClock, SaveManager и core technical integration. A2 — игрок/бой/исследование. A3 — хозяйство/ферма. A4 — задания/добровольные NPC. **A5 — главный агент, единственный разработчик всех UI, интеграция, QA**. **A0 — независимый сквозной сверщик и советник A5**. Технические процедуры в [плане](04-five-agent-workplan.md). Внешний UI меняет состояние только через публичные API; события публикуются только после commit.

## 7. G0 и фактический статус

Эта версия **предлагается к G0**. Утверждённые владельцем десять продуктовых решений и назначение A0 закреплены; точный контракт и документальные свидетельства ревью ещё должны быть проверены перед сменой статуса [Issue #4](https://github.com/AndreyCokol/My_shelter/issues/4) на APPROVED.

- **G0:** синхронизировать документы и контракты, проверить ссылки/версии, получить реальное ревью A1–A5/A0 и owner-approved SHA.
- **G1a после G0:** запустить стандартный Godot 4.7.2 GUI/headless и Windows export templates; собрать ядро и моки A1.
- **G1b:** A2/A3/A4 кодируют доменные модули, A5 разрабатывает весь UI, A0 ревьюит.
- **G4:** работает 15–35-минутный игровой сценарий и продолжение песочницы, Windows .exe с проверкой save/load.

**Фактическая реализация:** `NOT_STARTED`; наличие документа, пустого теста или PR не является доказательством работающей сборки.
