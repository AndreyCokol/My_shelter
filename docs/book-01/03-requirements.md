# Том 1 — основные требования к проекту (PRD / SRS)

**Продукт:** My Shelter · **Версия документа:** 0.1 · **Основа:** книга 1 «Картошка есть? А если найду?» (43 главы) · **Статус:** требования к разработке, **не заявление о готовности игры**.

## 1. Цель продукта

**[ПРОЕКТ]** Однопользовательская **2D pixel-art игра для ПК на Godot 4.x** с видом сверху, объединяющая исследование зомби-города, развитие персонажа и строительство собственного пространственного убежища.

**Ключевая фантазия:** игрок начинает один, почти без ресурсов, и благодаря особому убежищу способен накормить, защитить и переселить всё больше людей.

**Цель первого релизного этапа:** показать рабочую цепочку **пробуждение → бой → получение убежища → картофель → знакомство с выжившими → первые жители**. Полное прохождение сюжета первой книги — **последующий этап**, а не условие вертикального среза.

**Источники:** [механики](01-mechanics.md), [игровой сюжет](02-story.md), [досье книги](../../lore/books/01-kartoshka-est.md). Никакие события томов 2+ не используются.

## 2. Приоритеты

- **P0 / MVP:** критично для первого играбельного вертикального среза.
- **P1:** необходимо для полноценного игрового воплощения первой книги.
- **P2:** поздние, дорогие или потенциально необязательные элементы первой книги.

Числовые параметры, не заданные явно первоисточником (например, скорость персонажа или таблица урона), являются **[ПРОЕКТНЫМ БАЛАНСОМ]** и должны лежать в данных, не в коде.

## 5. Техническая схема Godot — [ПРОЕКТ]

```text
project.godot
game/
  autoload/
    GameState.gd
    SaveManager.gd
    EventBus.gd
    Rules.gd
  data/
    characters/   enemies/   items/   skills/
    crops/   buildings/   quests/   dialogue/
  scenes/
    prologue_hospital/
    paris_streets/
    louvre/
    shelter/
    ui/
  systems/
    combat/
    inventory/
    farming/
    settlement/
    economy/
    quests/
  tests/
docs/book-01/
lore/books/
```

Это **предлагаемая будущая структура**: создание данного документа не означает, что эти сцены или скрипты уже существуют.

### Правила архитектуры
1. **GameState** хранит только глобальное состояние кампании и ссылки на данные.
2. **EventBus** передаёт события `enemy_defeated`, `item_transferred`, `first_item_type_discovered`, `crop_harvested`, `resident_recruited`, `quest_completed`.
3. **SaveManager** сериализует данные сцен и список уже совершённых одноразовых действий (выдача награды, приём жителя, получение посылки).
4. **Rules** загружает настройки из Godot Resources/JSON. Конфигурационные числа делятся на **book_reference** (подтверждённые эпизоды) и **game_balance** (дизайн).
5. UI не изменяет состояние валют, XP или квестов напрямую — всё через методы систем, проверяющих условия.
6. Для массовой эвакуации использовать логические **группы** жителей. Выделенные NPC имеют отдельные объекты и идентификаторы.
7. Первые P0 механики должны быть реализованы **без** обязательной зависимости от P1/P2 модулей.

### Минимальная модель сохранения

```json
{
  "save_version": 1,
  "story_flags": [],
  "current_scene": "hospital",
  "player": {"health": 100, "level": 1, "xp": 0, "stats": {}},
  "shelter": {"level": 1, "xp": 0, "coins": 0, "discovered_item_types": []},
  "inventory": [],
  "containers": [],
  "crops": [],
  "residents": [],
  "quests": [],
  "game_time": 0
}
```

**[ПРОЕКТ]** Пример **формата**, а не подтверждение канонических стартовых значений здоровья, уровня, кошелька или характеристик. Реальный формат до реализации может измениться.

## 7. Сквозные приёмочные тесты

**E2E-01 — сюжетный старт.** Начать новую игру → выйти из капсулы → подобрать оружие → победить зомби → получить уникальный навык → войти в убежище. Проверить, что Система и награда выданы один раз.

**E2E-02 — выживание.** Открыть посылку с семенами и полем → подготовить место → посадить и полить картофель → **в обычном интерфейсе** выбрать «Дождаться урожая» в палатке → проверить игровое время и зрелость → собрать урожай, поместить часть в погреб и проверить отсутствие порчи. **Отдельный автоматический тест** применяет тестовый `GameClock.advance_for_test` для границ 72+12 часов, проверки порчи неубранного урожая и сохранности таймера после перезагрузки. Никакого ожидания 72 реальных часов.

**E2E-03 — двойная прогрессия.** Победить зомби → увеличился личный XP. Перенести ранее неизвестный тип предмета → вырос XP убежища. Второй предмет такого же типа не начисляет новый XP убежища.

**E2E-04 — первые жители.** Перейти в минимальную контактную зону у Лувра → оформить правила → получить согласие Алис и Пирра → **проверить, что без 2 картофелин переселение остаётся ожидающим** → доставить 2 картофелины в резерв прибытия **однократной транзакцией A1** → заселить обоих → завершить «Новые лица» ровно один раз → сохранить `job_id` без симуляции работы. Повтор диалога/транзакции не дублирует жителей, еду, квест или награды. Полный лагерь и торговля проверяются позднее по FR-16b.

**E2E-05 — сохранение.** Завершить E2E-01—04, закрыть приложение, запустить заново и загрузить игру. Все флаги, ресурсы, задания, позиции и таймеры сохранены, включая ожидание урожая и однократно предоставленный продовольственный резерв.

**E2E-06 — полная первая книга (после MVP).** Открыть финальный квест через сюжет → дождаться/сыграть неделю → проверить число подписавших договор жителей, включая ранее полученных → воспроизвести финальную сцену с предупреждением о вторжении; продолжение не выдумывается.

## 8. Не входит в этот проектный срез

- События и механики **томов 2–13**.
- Полная симуляция каждого жителя из тысячи спасённых.
- Многопользовательская игра, облачные сохранения, аккаунты и сервер.
- Полноценная карта всех стран, мировой экономики и множества иномирных цивилизаций.
- Реализация всех уникальных предметов и навыков серии до проверки основных циклов.
- Подмена книжного канона игровой математикой без маркировки [ПРОЕКТ].

## 9. Решения, которые нужно зафиксировать до разработки

1. 16×16 или 32×32 тайл и базовый размер спрайтов.
2. Режим камеры (предлагается сверху) и форма боя (реальное время с паузой или без).
3. На G0 утвердить соответствие реального времени и игровых часов; в автоматических тестах использовать детерминированную команду продвижения `GameClock`, сохраняя книжные интервалы.
4. Насколько близко воспроизводить контракты, насилие и взрослый юмор книги.
5. Правовой статус публичной/коммерческой адаптации и использование оригинальных имён.
6. Формат диалогов и персонажей (сценарные NPC в MVP, агрегированные жители в поздних актах).

**Критерий готовности MVP:** E2E-01—05 проходят на Windows-сборке и в редакторе Godot 4.x, сохранение работает после перезапуска, пройден тест UX-01 ниже. Пока нет игрового проекта и результатов запусков, критерий **не выполнен**.


## 10. Проверка игрового опыта — [ПРОЕКТ, P0 для G4]

**UX-01 — малый внешний плейтест.** После интеграции дать вертикальный срез минимум **5 игрокам**, не участвовавшим в реализации (тест с наблюдением, без подсказок, кроме явного обучения в игре). Записать анонимно: где игрок застрял, причину непонимания, время прохождения, число запросов помощи и умеет ли объяснить пользу еды/поселения.

**Критерии G4:** минимум **4 из 5** самостоятельно выполняют путь до урожая и первых жителей; минимум **4 из 5** могут словами объяснить, зачем нужен картофель, и находят путь к следующему действию в пределах **2 минут** после обучающей подсказки. Целевое время **15–35 минут** на первый законченный игровой цикл (без реального 72-часового ожидания); это гипотеза баланса для проверки, не канон. Если метрика не пройдена — статус **UX_FAIL**, правки и повторный плейтест, не маскировать результат зелёными unit-тестами.

**А5** ведёт протокол наблюдения, **A1** исправляет системные барьеры, A2–A4 — дефекты своих модулей. Отдельно в G2/G3 провести внутренний UX smoke, чтобы не откладывать весь фидбэк до финала.
