## 2. Зафиксировать границу игрового и реального времени

**GameClock** — один календарь целых игровых минут, не Godot physics timer. Накопление реальных delta производится дробным аккумулятором, переход границы игровой минуты детерминирован, пауза останавливает аккумулятор. A2 использует физические frame delta только для движения/ударов/dodge и не передаёт боевой cooldown в растение или сюжетный таймер. При save сохранять `game_time_minutes`; дробный остаток можно сохранить отдельно, если он влияет на точность продолжения, иначе явно округлять вниз с ограничением (без скачка времени на перезапуске).

**На отдыхе** A1/A3/A4 рассматривают несколько дедлайнов (растения, порча, будущие квесты) и останавливают отдых перед необратимым важным игровым выбором. Если нет safe area или целевого deadline, вернуть отказ с пояснением. UI A5 отображает дату/время результата до подтверждения и различает обычное ожидание и действие сна.

## 3. Важная граница команд и ревизий

- **Не сериализовать в диск каждую атаку, движение или animation frame.** Реальный бой A2 исполняет динамику кадров в runtime; долговременные эффекты (побеждённый `enemy_id`, награда, XP, уникальный лут) проходят координатор A1 один раз и сохраняются.
- `state_revision` в snapshot меняется, в том числе из-за календаря. **Нельзя заставлять любую покупку проваливаться из-за невидимого тика.** Для расхода/согласия/продажи использовать `expected_resource_revision` затронутого объекта; при подлинном конфликте UI показывает `STALE_REVISION` и обновляет экран.
- Повторное получение квитанции по старому `action_id` после save/load возвращает исходный результат, **не** выдаёт предмет снова; транспортные поля (expected revision) не меняют смысл отпечатка исходного запроса.
- Для `arrival_food_requirement`: только положительные значения `units_per_resident`; старый save сохраняет `ruleset_version`, миграция баланса не пересчитывает старый резерв молча; `reserve_mode` различает выделенный запас и окончательное списание.

## 4. План передачи после принятия G0

1. **A1/G1a** проверяет actual Godot 4.7.2 GUI+CLI и шаблоны Windows; создаёт `project.godot`, `Main/WorldHost`, InputMap, `GameCoordinator` mock/contract tests и `SaveManager` skeleton. Отчёт `command, version, OS, log, PASS/FAIL`.
2. **A2/G1b** запускает сцену больницы и боевой controller с dodge, удостоверяет one-time System reward.
3. **A3/G1b** запускает убежище, 2 поля и оба режима ожидания, без UI в своём каталоге.
4. **A4/G1b** предоставляет optional quest predicates, voluntary consent/recruitment, без прямой записи инвентаря.
5. **A5/G1b** самостоятельно пишет **весь UI**, контролирует InputMap, mock integration и Windows/user acceptance. **A0** отдельно читает P0 PR A5, консультирует и сверяет контрактные/пользовательские сценарии.

## 5. Правила GitHub claims без фиктивных блокировок

- Рабочий источник истины — Issue с одним назначенным ответственным, acceptance criteria и ссылкой на PR.
- `claims/book-01/<TASK-ID>` — **видимый маркер**, не атомарный замок: перед работой проверить и ветку, и Issue, и PR. A5 разбирает конкурентные претензии и замороженные задачи.
- При отсутствии активности/незавершённом claim: не захватывать молча; A5 документирует отвод/передачу задачи, новый исполнитель отходит от свежей базовой ветки.
- Каждый разработчик пишет только в свою область. PR по контракту затрагивает A1+A5 и владельцев потребителей; независимое ревью кода A5 проводит A0 или другой не-автор.
