## Сильные стороны оригинала
- Строго ограничивает том 1 и конец на Тэрр Гэ (§1, §4).
- Не выдаёт документ за исполняемую игру (§1, §11).
- Явные отдельные домены A1–A5 (§3, §7).
- Атомарность и `action_id` (§7).
- Использует G0–G6, PR и запрет прямых коммитов в main (§8).
- Требует тесты и лицензии ассетов (§9).

1. В **COMMON.md** исправлены приоритеты, добавлено формальное доказательство G0 и перечень допустимой работы до G0.

6. Подготовлены пять индивидуальных промптов (A1–A5) с задачами, исключительными файлами, действиями на G0, критериями по текущему gate и отчётами.

## Незакрытые организационные вопросы
- **G0 ещё не утверждён:** договоры `05-integration-contracts.md` помечены DRAFT, требуется решение владельца и фиксация версии.
- **Godot-проект ещё не найден в `main` по состоянию проверки:** игровая сборка и E2E не подтверждены. После слияния промптов повторить аудит репозитория.
- **Блокировка конкурирующих задач не обеспечивается одним GitHub Issue.** Для реальной параллельной работы обеспечить короткое закрепление задачи на время выполнения, честный повторный check перед push и ревью A1.
- Открытый [PR #1](https://github.com/AndreyCokol/My_shelter/pull/1) содержит исходный COMMON. **Эта ревизия — кандидат**, не самовольное «принятие» G0 или публикация в main.

## Итоговый порядок принятия
1. Ревью этого аудита + новых промптов, выбрать итоговый PR.
2. Принять G0 отдельным подтверждённым решением с commit SHA.
3. После разрешения владельца начать A1-01/A1-02, подготовить заглушки для остальных.
4. Параллельно A2–A5 реализуют P0 только в своих папках, отдельными PR.
5. A5 и A1 совместно принимают сквозной маршрут на Windows с сохранениями, без заявления об успехе до тестов.
