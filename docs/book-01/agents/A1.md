## Общие правила работы
1. Сначала проверить актуальную ветку, Issues, контракты и чужие открытые PR. Взять **только свободную задачу своего ID**, зарегистрировать владельца в Issue и работать в отдельной ветке `agent/<id>/<task-id>-<slug>`. Если Issues нет — предложить/создать свою задачу до изменения кода (не объявлять её занятой без записи).
2. Не редактировать исходники другого агента. Предлагать изменение контракта через Issue/PR, не внедрять самовольно альтернативный API.
3. Отличать **[К]** (книга 1) от **[П]** (дизайн/баланс), не добавлять события томов 2+. Канонические числа сверять с указанными главами.
4. Для результата нужны тесты, запуск проекта Godot (когда код появится), PR и краткий отчёт: `task | status | commit/PR | tests | blockers | changed contracts`.
5. Новые незафиксированные решения сначала документировать. Никаких прямых изменений `main` при параллельной разработке.

## Миссия
Единственный владелец **общего ядра**, контракта сервисов и процесса мерджа. Создать основу, с которой остальные 4 агента могут работать независимо.

## Исключительные пути
`project.godot`, `game/autoload/**`, `game/systems/core/**`, `game/systems/inventory/**`, `game/systems/progression/**`, `game/scenes/main/**`, `game/tests/core/**`, `game/tests/integration/**`, `.github/workflows/**`, [интеграционные контракты](../05-integration-contracts.md).

## Наряды
- **A1-01 / P0:** создать Godot 4.x проект и структуру, ввод, главную сцену/переходы, шаблоны тестов и headless-проверку.
- **A1-02 / P0:** `GameState`, `EventBus`, единые игровые часы, система команд и G0-заглушки для A2–A5. Фиксировать публичные API вместе с ними.
- **A1-03 / P0:** единый инвентарь (без дублирования), операции с монетами, почта/посылки как **данные и доменные команды**, вознаграждение `grant_once`, уникальные ID.
- **A1-04 / P0:** личный XP и XP убежища (новый тип предмета = опыт один раз), переход в убежище и возврат на внешнюю карту. UI делает A5.
- **A1-05 / P0:** `SaveManager`, `save_version`, единая сериализация, приём чужих модулей через PR, headless smoke, Windows x64 экспорт и E2E-05.
- **После MVP / P1:** интеграция расширения территории, обороны, заданий и финального акта книги 1.

## Очерёдность
1. Утвердить G0 с A2–A5; определить стабильные имена API, события, `GameClock`, формат сохранения и правила транзакций.
2. Сделать мини-проект и заглушки, открыть доступ остальным агентам к публичному API.
3. Объединять подсистемы только через PR; запрещено копировать их игровую логику в `GameState`.
4. Пройти G2–G4 с тестами и отчётами.

## Проверки
- Сцена открывается после перезапуска Godot без ошибок ресурсов.
- Повтор `action_id` не выдаёт монеты, XP, жителя или посылку повторно.
- Вторая копия уже исследованного `item_type_id` не повышает XP убежища.
- Трансфер предметов и загрузка сохранения не меняют суммарное количество экземпляров.
- Сохранение доступно после закрытия игры; часы фермы/квестов не сбрасываются.
- **Мерж не считать тестированием:** отдельные green-тесты и ручной проверочный маршрут.

## Не делать
Не рисовать сцены Парижа, фермы и Лувра; не выполнять работу A5 по UI и ассетам; не писать новые события книг 2+. До реальной интеграции не рапортовать о готовой сборке.
