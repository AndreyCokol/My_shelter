# 09 — Sandbox Gameplay Design: свободная игра по мотивам

**Статус:** G0 CANDIDATE · **Приоритет:** P0 для игрового поведения; численный баланс не заморожен. Основание: OD-01/02/03/04/06/08/09/10 в [реестре](08-g0-decision-record.md).

## 1. Основная игровая петля

```text
Выбрать занятие → исследовать / сражаться / добывать / ухаживать за полем
       ↘              ↓                      ↙
         вернуться / перенести ресурсы / сохранить
                           ↓
                улучшить запас / XP / место
                           ↓
              новый выбор без обязательного квеста
                           ↺
```

**Игрок имеет автономию.** Сценарные задания объясняют, мотивируют или предлагают новые цели, но не являются обязательным флагом для уже разблокированных базовых функций. Обязательный onboarding допускается только для открытия базовых механик Системы и убежища. После Q01/Q02 у игрока есть минимум две содержательные цепочки вне сюжетного журнала: (а) посев/сбор/склад; (б) вылазка/бой/сбор внешних ресурсов. Они должны сохраняться после закрытия Q07 и при отсутствии активного Q03–Q07.

## 2. MVP на 15–35 минут: единица законченного опыта

Первая играбельная версия не обязана представлять все 43 главы. Она должна дать:
- Пройти вступление и открыть базовые способности (недублируемая награда);
- Самостоятельно управлять реальным боем: движение, атака, уклонение, оружие;
- Войти/выйти из пространственного убежища с сохранением позиции мира;
- Получить семена, посадить и полить, использовать обычное время **или** отдых; собрать урожай и хранить его;
- Поговорить с добровольными NPC и понять отображаемые условия заселения (количество еды из `arrival_food_requirement`);
- Сделать выбор следующей деятельности, получить/не получить жителей, сохранить и загрузить, продолжить игру.

**15–35 минут — целевая UX-гипотеза**, замерять по реальным новичкам/внутреннему smoke; не искусственно укорачивать игровые часы только ради этой цифры. Нет обязательного «выиграть всю книгу». Специально проверить обходной сценарий: игрок не делает Q03–Q07, но выращивает картофель, торгует с системным магазином при наличии ресурсов и исследует доступный район.

## 3. Время, сон и обратные связи

- Один `GameClock` `game_time_minutes` (A1). Естественный рост и rest влияют на одну модель A3/A4, а не отдельные таймеры UI.
- Реальный коэффициент `minutes_per_real_second` — баланс. Интервалы картофеля в книге (72/12 игровых часов) — справочные, но `grow_minutes`/`spoil_minutes` хранить в `game_balance`.
- Отдых — доступное **игроку** действие в безопасной палатке. A5 показывает время, прогноз готовности и опасные предупреждения; при отказе ничего не меняется.
- Если отдых перескакивает значимые интерактивные события, остановить время на событии/предупредить по принятому сценарию, не пропускать молча. Все поля и сроки оцениваются после `advance` в детерминированном порядке.
- QA advance отдельно и только в тестовом окружении, не заменяет игрового действия отдыха.

## 4. Хозяйство и пищевое обеспечение

- Цикл crop: `EMPTY→TILLED→PLANTED→WATERED→GROWING→RIPE→SPOILED` с однократным `try_harvest`; при переполнении инвентаря поле остаётся ripe.
- Источник воды, запас семян, доступные клетки и контейнеры ограничивают действия; продвинутые постройки позднее.
- Продовольственные условия от `arrival_food_requirement`: `accepted_food_type_ids`, `units_per_resident`, `reserve_mode`. **Баланс задаёт значение** и может меняться после внутреннего теста; никакого скрытого обязательства двух картофелин. UI показывает расчёт и фактический остаток.
- Согласие на присоединение отделено от наличия продовольствия. Уникальные NPC не дублируются при двойном нажатии и перезапуске.
- Регулярные голод, производство и потребление ресурсов жителей остаются P1 — нельзя ложно обещать их в P0. Базовый `job_id` может сохраняться без работы.

## 5. Бой и исследование

- Real-time: движение, направление атаки, `attack`, `dodge`, cooldown/stamina **только если оправдано балансом**, попадание/урон, визуальная обратная связь, урон игроку, восстановление после поражения по определённому игровому правилу.
- P0: один работающий тип обычного заражённого, тестовая зона больницы и доступный небольшой участок города. А2 выбирает допустимый способ respawn/повторяемой добычи без клонирования сюжета и бесконечных уникальных наград.
- Первая системная награда — однократна даже при повторе death signal. Повторяемый бой может давать **обычное** XP/ресурсы по отдельным правилам баланса, но не стартовые уникальные rewards.
- Сюжет не должен быть единственным источником ресурсов, необходимых для продолжения песочницы после onboarding.
- **P0 anti-softlock:** один доступный интерактивный ресурсный узел в городской зоне (A2) даёт повторяемые простые семена/расходники по `resource_respawn_minutes` из баланса. Состояние `resource_node_id`, `last_claimed_game_minute`, `next_available_game_minute` сериализуется; повторное посещение сцены **само по себе не сбрасывает cooldown**. Выдачу согласует A1 Inventory и защищает по `action_id` и устойчивому узлу/циклу. При полном инвентаре ресурс остаётся доступным.
- **P0 восстановление после поражения:** без безвозвратного удаления кампании. После смерти игрок восстанавливается на последней безопасной точке с понятным UI A5, уникальные награды и события победы не повторяются. Потеря предметов/штраф за смерть не обязательны для первого прототипа и требуют отдельного балансного решения A5.

## 6. Переходы, доступ и опасность софтлока

**Минимальные capability flags:** `system_unlocked`, `shelter_unlocked`, `inventory_available`, `farming_available`, `city_area_available`. Квестовые флаги наблюдают эти состояния, но не обязаны активировать базовые операции после открытия. При `Q03=AVAILABLE` можно посадить; при `Q05=LOCKED` доступный район остаётся открытым, если не зависит от реального сюжетного барьера.

**Проверить отрицательные маршруты:**
- игрок потратил стартовый ресурс до Q07: остаётся способ добыть/купить еду в уже реализованном P0;
- игрок не выполнил учебный квест, но обладает открытой механикой: она действует;
- игрок не может безопасно ждать из-за опасности: есть понятный путь убрать опасность или подождать естественно;
- несколько посевов имеют разные `ready_at`: отдых не портит остальные без предупреждения;
- переполненный склад не уничтожает урожай/добычу;
- `SaveManager` восстанавливает автономные действия без повторного сюжетного награждения.

## 7. Содержание и права

Для широкой аудитории: ясная добровольность взаимодействий, нет сексуального насилия или эксплуатации в механиках, не копировать откровенные диалоги. Опасность/смерть — без натуралистических сцен. Только личный закрытый прототип, все сторонние ассеты по условиям лицензии, никакого публичного распространения без отдельного решения и проверки прав на литературную адаптацию.

**ВЕСЬ осколок LATER** (не создавать сюжетное событие, сцену, квест, battle или обязательную предпосылку в текущей кампании). Поздние 1000 жителей/7 дней из литературного источника — потенциальная необязательная сюжетная ветка, а не обязательный дедлайн всей игры.

## 8. Приёмка независимости песочницы

- **SB-01:** после Q01/Q02 запустить поле и хранение при `Q03..Q07 = AVAILABLE/INACTIVE`.
- **SB-02:** выйти в доступную зону, найти/получить обычные ресурсы и вернуться без старта Q05.
- **SB-03:** завершить Q07, продолжать рост поля и исследование, save/load не приводит к «концу книги».
- **SB-04:** не хватает еды/места/воды — UI сообщает почему и показывает доступный путь продолжить.
- **SB-05:** смерть первого заражённого с повтором сигнала не выдаёт вторую стартовую награду; обычные repeatable столкновения отделены.
- **SB-06:** 15–35 мин измеряются в реальном прототипе; статус `NOT_MEASURED` пока игру нельзя запустить.

Сверка A0: для каждого SB проверить цепочку `FR → UI A5 → публичная команда → domain A1–A4 → save → E2E`. Реальные тесты пока `NOT_RUN`.
