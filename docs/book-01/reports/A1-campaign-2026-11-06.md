## Исправленные проблемы

- CoreSession теперь использует внедряемые normalize/plan/validate callbacks и единый commit/recovery для реальной поддержанной campaign-схемы. Старый core.increment остался только bootstrap fixture.
- Реализованы покупка, перенос/разделение стеков, посылки и одноразовые награды; XP героя и убежища независимы. Цены и выдаваемые предметы берутся из доверенного каталога; UI не задаёт цену или произвольный loot.
- Покупки/переносы требуют ревизий затронутых контейнеров/кошелька/offer; пропущенная ревизия отклоняется. При конфликте возвращаются conflict_keys. Тик Clock меняет общую revision, но не ревизию инвентаря.
- Идемпотентность проверяется до текущей сцены и ревизий. Уникальные parcel/reward IDs защищают и от повторов с новым action_id. Неуспешная команда не оставляет receipt, списанных монет, изменённых XP или предметов.
- Clock хранит целые минуты и дробный остаток в общем состоянии. Tick выполняется без дисковой записи на кадр, следующий durable checkpoint сохраняет согласованный snapshot. Explicit session.save работает из pause menu, а покупки и tick на паузе запрещены.
- Схема проверяет ссылки item→container, capacity, типы/количества, правила, scene IDs, receipts и уникальность. Неподдержанные непустые crops/residents/quests/reservations отклоняются целиком до появления доменных import hooks.
- Исправлен выявленный тестом дефект Godot JSON: целые числовые поля возвращались как float; теперь безопасные целые нормализуются до проверки/замены DTO. Дробные остатки сохраняются.
- Исправлено время жизни доменного обработчика: coordinator удерживает владельца callbacks. Устранён цикл ссылок validator→session, который давал утечки при выходе.
- Тестовый runner ограничивает длительность, проверяет точную версию, completion marker, код процесса, SCRIPT ERROR/ERROR и утечки. Нулевого exit code Godot недостаточно для PASS.

## Реальный объём API

Создать CampaignSession с доверенными rules: version, items, offers, parcels, rewards, scenes, containers, discovery_xp, minutes_per_real_second. Невалидные rules не создают coordinator. Сохранять отдельно от старого core-bootstrap slot. Catalog version неизменяем: изменение правил требует нового version и явной миграции, которой пока нет.

Через campaign.coordinator:

| command_type | payload | Ресурсные ревизии |
|---|---|---|
| inventory.purchase | offer_id | inventory:player, wallet, offer:ID |
| inventory.transfer | instance_id, from_id, to_id, quantity | inventory:FROM, inventory:TO |
| inventory.claim_parcel | parcel_id | inventory:player |
| progression.claim_reward | reward_id | inventory:player |
| clock.rest | target_minute | Нет; safety по авторитетной сцене |
| scene.transition | destination_scene_id, entry_point_id | scene |
| session.save | пустой объект | Нет |

Каждый envelope содержит action_id, command_type, payload, context.actor_id=player, context.scene_id и expected_resource_revisions для перечисленных сущностей. Реальная сцена сверяется после replay. Использовать get_snapshot() для актуального UI, не revision исторической квитанции.

**Ограничения интеграции:** scope=campaign-core — поддержанный поднабор CampaignSnapshot, не полная схема всей игры. Scene transition меняет согласованные DTO, но ещё не инстанцирует карту/героя. Rest пока разрешён только при пустых неподключённых доменах; гарантии зрелости/порчи — будущая поставка A3. Каталожный eligible — техническая заглушка доверенного eligibility, а не выполненные quest/combat predicates; не подключать кнопку выдачи наград игроку до интеграции A2/A4. Catalog fixtures находятся только в тестах и не являются продуктовым балансом. Main ещё запускает bootstrap, не кампанию с тестовым каталогом.
