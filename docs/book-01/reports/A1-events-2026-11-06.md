# A1-02: post-commit события и жизненный цикл подписок

Дата: 2026-11-06. Исполнитель: Codex, A1, одна сессия. Issue #23. База PR #22 / 8d1804bb36f09ceba07f99eb29a314738b53188d. Independent review: REVIEW_NOT_PERFORMED.

## Изменение поведения

Ранее ядро имело только compatibility signals committed/state_loaded; полноценный DomainEvent/EventBus из контракта отсутствовал. Добавлен EventBus со стабильными event IDs и envelope, фильтрами, weak owner, idempotent subscribe/unsubscribe и копиями payload на каждого слушателя. Снятые/уничтоженные подписки не получают события, новые во время dispatch подключаются со следующего факта. Скрываемые без уничтожения окна должны явно отписываться.

CoreSession принимает чистые event drafts от planner, проверяет их до записи, публикует после snapshot commit и runtime install. На replay/ошибке/прерванном commit нет новых фактов. Listener видит уже согласованные state/world; reentrant команда или публикация отклоняется. События не начисляют ресурсы и не заменяют persisted receipts.

Inventory/Progression/Scene/Clock теперь уведомляют о реально выполненных изменениях: перенос/выдача предмета, discovery, посылка/награда, раздельные XP, монеты, сцена, время и explicit save. scene_changed использует entry_point_id и return_scene_id вместо неоднозначного return_point_id. Контракт v1.3-PROPOSED требует review будущих потребителей, не объявлен утверждённым.

Tick публикует time_advanced на границе календарной минуты, без записи checkpoint на кадр. Rest использует тот же envelope. После load/recovery сохраняются живые UI subscriptions, сбрасывается transient delivery history и публикуется state_loaded для повторного snapshot. Исторические игровые факты не проигрываются заново; их последствия уже сохранены.

## Передача A5 и доменным разработчикам

Подписка: main.session.events.subscribe(panel, panel.on_domain_event, ["event_type"]); хранить token и снимать его при закрытии/выходе панели. Повторно использовать стабильный bound method, а не создавать новый lambda на каждое открытие. В callback читать snapshot для отображения. Для действий пользователя отдельная команда после завершения текущего commit.

Доменный planner возвращает events:[{event_type,payload}] внутри успешного плана, без самостоятельного EventBus publish и side effects. Координатор добавляет action_id, event_id, revision и game_minute. При ошибке draft весь план отклоняется до I/O.
