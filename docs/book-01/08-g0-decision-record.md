## 3. RACI и роли без нарушения общего промпта

| Операция | A5 (главный) | A1 (тех. интегратор) | A2/A3/A4 | Владелец |
|---|---|---|---|---|
| Декомпозиция, повестка, блокеры, проверки PR | **R** | C | C | A по scope |
| Глобальные игровые контракты, API, save | C/ревью | **R** / владеет файлами | C по своим интерфейсам | **A** на G0 |
| Core, GameClock, merge, CI | C/QA veto | **R** | I | A по gate |
| Боевой/фермерский/сюжетный код | QA & integration audit | интеграционное ревью | **R** каждый в своей зоне | A по scope |
| UI, лицензии ассетов, E2E, UX | **R** | C | C | A при релизе |
| Утверждение G0, изменение scope, публичный выпуск | формирует evidence | предоставляет тех. evidence | ревью контрактов | **Единственный A** |

R — исполнитель; A — окончательное решение; C — consulted; I — informed. A5 **не** получает право напрямую менять A1 GameState/SaveManager только потому, что главный. A1 **не** может самовольно утвердить G0. В случаях спора агент блокирует действие и поднимает решение владельцу.

## 4. Что конкретно ещё не хватает для старта

### Critical / G0 blockers
1. **Единая принятая версия документации.** Устранить различия main ↔ PR #2: питание 2 первых жителей, один зомби, sleep/QA, приоритеты, форматы событий и сериализации. Закрыть/заменить PR #1 и вылечить конфликты PR #2, не объединяя их как две истины.
2. **Контракт API v1.** Нормализовать `command`/ `event_type`/ `event_id`/ `action_id`, result/error codes, ownership, idempotency, atomicity, cross-domain receipts, одинаковую единицу времени, правила migrations. Переписать согласованный [05](05-integration-contracts.md) или объявить [07](07-contract-spec-proposal.md) его утверждённой заменой — не оставлять одновременно два несовместимых нормативных источника.
3. **Зарегистрировать технические ADR** D-01..D-16, точную версию, основные параметры, архитектуру модулей и источники canonical/project; каждому решению статус `APPROVED`, `REJECTED` или `AMENDED`, ссылку на GitHub owner comment. Не ставить APPROVED автоматически.
4. **Сценарные DTO и данные P0.** `Q01..Q07`, флаги System unlock, первый zombie, parcels, crop recipe, residents Alice/Pirr, available item types, сохранения и UI states. Указать `owner`, `source_ref`, `game_balance` для любого числа вне канона.
5. **Набор тестовых фикстур.** Empty new game, after combat, after planting, 72h/84h, 1 and 2 potatoes, before/after recruitment, corrupted save, duplicate action, relaunch/resume.
6. **Ревью и merge strategy.** A1/A2/A3/A4/A5 документируют review с реальными ссылками/комментариями и SHA. G0 нельзя принимать по словам одного агента.
7. **Проверка лицензирования ассетов/исходного произведения** и редакторских границ — как минимум явный release gate; не считать отсутствие решения разрешением публичной публикации.

### Не блокирует G0, но блокирует позднейший G1/G4
- Загрузка конкретной версии Godot/Windows export templates, `project.godot`, игровые ассеты, CI, headless smoke и физический Windows экспорт — **это работа после G0**, а не условия для самовольного написания кода до G0.
- 60 FPS и UX-01 требуют реального Godot-прототипа; на G0 фиксируются только измерения/критерии.
- Полный лагерь Лувра, P1 голод и производство, оборона, 1000 жителей, P2 осколок не блокируют первую играбельную версию.
