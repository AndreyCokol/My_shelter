# План разработки: четыре доменных разработчика, главный A5 и независимый A0

**My Shelter · G0 CANDIDATE 2.0 · 2026-11-05.** Пять основных разработчиков A1–A5 + дополнительный агент A0. Проектные назначения конкретизируют [универсальную модель General-Archive 2.0](https://github.com/AndreyCokol/General-Archive/blob/main/docs/MIGRATION.md); сам архив не переназначает роли автоматически.

**Решения владельца:** песочница с сюжетными заданиями, real-time атака/уклонение, естественное время и отдых, настраиваемый пищевой резерв, **A5 — главный и единственный разработчик всего UI**, свободная адаптация и переработка взрослых тем, весь пространственный осколок отложен, MVP 15–35 минут, только личный закрытый прототип. A0 помогает/ревьюит A5, не заменяя его.

**A5 — главный; A1 — технический владелец ядра и его integration files.** A5 координирует общую интеграцию и приёмку, но изменения файлов A1 проходят ревью владельца. A1 не руководит проектом вместо A5. A0 — advisor/checker, не третий центр управления.

**Окончательное решение владельца:** изменение концепции/объёма, публичный выпуск, G0 и другие явно выделенные контрольные точки. **A5** может решать технические детали и распределять работу по принятой архитектуре, а также выбирать размер тайла по действительному визуальному прототипу. A1 фиксирует выбранную стабильную версию движка/совместимость в технических результатах.

## 2. Совместное владение и интеграция

- `game/data/**`: только модуль-владелец создаёт свой каталог (A1 `items/rules`; A2 `enemies/loot`; A3 `crops/buildings`; A4 `quests/dialogue/residents`). Для общего каталога API — решение A1 + ревью A5.
- Общие контракты `docs/book-01/05-integration-contracts.md` и `game/contracts/**` — **редактор A1, review A2–A5 и A0 по риску**; breaking change только через Issue/ADR.
- Все визуальные окна (HUD, уведомления, системный магазин, инвентарь, ферма, диалоги, квесты, настройки, ошибки сохранения) **пишет A5**; A1–A4 предоставляют DTO/команды, не создают собственные конкурирующие окна.
- `game/scenes/main/**` (composition root/WorldHost) редактирует A1. A5 предоставляет отдельно инстанцируемый `UILayer`; integration via contract, без несанкционированного редактирования общей сцены.
- **A0** не изменяет код без поручения; может независимо фиксировать блокирующий дефект A5 и эскалировать владельцу проекта.

Для мелких косметических правок — risk-based review.

## 5. GitHub: конкуренция и совместная работа

1. **Issue — источник задачи**: `[A3-01] Growth/Clock`, owner, scope, acceptance, ветка/PR, ссылки на контракт. Если задач ещё нет, создать перед первым изменением кода после G0.
2. **Захват задачи:** перед началом проверить Issue/assignee, открытые PR и claim-ветку `claims/book-01/<TASK-ID>`. При нескольких претендентах A5 явно выбирает одного. **Наличие ветки не гарантирует атомарную блокировку само по себе** — повторная проверка перед записью обязательна.
3. **Ветка исполнителя** `agent/<id>/<TASK-ID>-<slug>`. Не коммитить напрямую в `main`; при изменении owner-файла без поручения создавать Issue с предложением.
4. **Зависимости:** A1 publ. API/тестовые stubs G1a → параллельные A2–A5 G1b. При breaking API change — Issue `[CONTRACT]`, affected owners, новая версия DTO/миграции и review.
5. **PR:** связь FR/NFR, task ID, commit, expected/actual, точная команда проверки + версия среды, PASS/FAIL/NOT_RUN. Нет независимого ревью собственного PR. A5 держит общую очередь; A1 мержит код ядра/композиции при подтверждении A5, чужие каталоги остаются за владельцами.
6. **Stale claims:** A5 разбирает зависшие задачи с фиксацией отмены/передачи, вручную обновляет Issue и закрывает/архивирует устаревшую ветку; без неявного захвата чужой работы.
7. **Сохранение документации:** исторические PR и аудиты — источники, но **нормативно только замороженный в G0 SHA**, а не одновременно main/черновые ветки.

## 6. Отчёт и честный DoD

`agent | task | PR/SHA | changed files | FR | tested command/environment | PASS/FAIL/NOT_RUN | reviewer | blockers | next owner`.

**DoD:** код не нарушает чужих зон, контракт соответствует принятой ревизии, есть негативные тесты и корректный экран ошибки; checked Godot export vs `NOT_RUN` различены. Подтверждение A5 недостаточно для собственного критического PR — нужен независимый review. Назначение агента в документе **не означает**, что отдельные автономные процессы уже запущены.
