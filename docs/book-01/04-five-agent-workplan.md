# План разработки книги 1 силами пяти изолированных агентов

**My Shelter · Godot 4.x · 2D pixel-art · версия плана 1.0 · статус: PLANNED**

**Источник требований:** [механики](01-mechanics.md) · [сюжет](02-story.md) · [PRD/SRS](03-requirements.md) · [первый том](../../lore/books/01-kartoshka-est.md). **Строго одна книга:** не добавлять сюжеты и механики последующих томов. Папки `game/`, `project.godot` и сборка здесь описаны как **планируемые**, а не существующие файлы.

## 1. Цель и границы

**MVP:** пробуждение Сергея в больнице → первое системное убийство зомби → открытие личного убежища → получение посылки → посадка и сбор картофеля → короткая контактная зона у Лувра → контракт с Алис и Пирром → сохранение / загрузка. Игрок получает раздельный опыт героя и убежища; **в настоящем игровом UI** может дождаться урожая из палатки, а **2 единицы картофеля [П]** однократно выделяет на снабжение Алис и Пирра. Только после снабжения они переезжают и закрывается «Новые лица». Сохранённый `job_id` пока не запускает симуляцию труда/голода. MVP — короткая зона у Лувра, **не** полный лагерь. Готовность: E2E-01—05, Windows x64 и **плейтест UX-01**.

**После MVP (P1):** полный лагерь Лувра и торговля, симуляция производительности/потребления пищи жителей, оборона, более широкая экономика, квест с эвакуацией **1000 договорных жителей за 7 игровых дней**, финальная сцена с предупреждением о Тэрр Гэ. **P2:** первый пространственный осколок, расширенные награды. Финал вторжения не придумывать.

Принцип: **сначала реализуем играбельный вертикальный срез, затем масштабируем**. Критерии успеха — E2E-01—05 из [требований](03-requirements.md), а не число написанных скриптов.

## 6. Процесс GitHub для 5 агентов

1. **Одна задача — один владелец:** Issue `[A3-02] Поле и урожай`, ID, PR и метки `book-01`, `agent:A3`, `priority:P0`, `status:in-progress`. **Для конкурентного захвата:** агент сначала убеждается, что ID отсутствует среди чужих активных PR/Issues, затем **атомарно пробует создать** уникальную Git-ветку-маркер `claims/book-01/A3-02` с текущего `main` (GitHub отвергнет создание существующей ссылки). Только успешное создание + подтверждённая запись в Issue позволяют работать. При конфликте, неизвестном ответе GitHub или невозможности проверить маркер — `BLOCKED`, решение A1. Старый маркер не удаляют/не переназначают самостоятельно; A1 освобождает его вручную после закрытого PR и подтверждения. **Пока задачи не зарегистрированы**; эта таблица — план, не реальные Issue.
2. **Отдельная рабочая ветка / PR**: `agent/a3/A3-02-farming` отличается от маркера `claims/book-01/A3-02`; PR указывает FR, главу книги, ссылку на Issue, claim и тесты. Перед первым push **повторно** проверить Issue/claim/чужие PR.
3. **Один владелец файла**: изменение чужой подсистемы только через Issue/предложение владельцу; общие контракты изменяются после ревью A1 и затронутых агентов.
4. **Договорённости — в Git**: API, сохранения, схемы данных, критические решения и смещения от канона фиксировать в `docs/book-01/`.
5. **CI-гейты**: проверка запуска Godot headless, тесты модулей и общего smoke. A1 мержит в `main` после зелёных проверок. Никаких прямых коммитов в `main` от параллельных агентов.
6. **Короткая интеграция после каждого gate:** A1 принимает минимально завершённые PR, проверяет headless smoke и сохраняет играбельную `main`. Синхронизация обязательна при каждом изменении публичного API, формата сейвов, ассетов или межагентных зависимостей.

**Формат отчёта агента:** `ID задачи | статус | PR/commit | что сделано | тесты | блокеры | какие контракты затронуты`.

**Definition of Done для задачи:** собственный код, обновлённые данные/контракты при необходимости, тесты, проверка загрузки Godot, ссылка на источники [К] либо пометка [П], PR без изменений чужой зоны, ревью интегратора. «Написал скрипт» без проверки — не Done.

## 7. Риски, границы и нерешённые решения

- **Узкие места:** A1 (API и сборка). Снижаются **G1a — только ядро и заглушки**, затем независимыми PR G1b, контрактными тестами и короткой интеграцией после каждого gate. A5 не становится «владельцем игрового состояния».
- **Первый картофель нужен игроку:** [П] 2 единицы урожая резервируются на первых переселенцев один раз; автоматический голод/производительность — лишь P1.
- **Игровое ожидание урожая:** действие у палатки в обычной игре; общий GameClock обрабатывает время детерминированно. Команда QA-only не может быть доступна обычному игроку.
- **Проверка увлекательности:** 5 внешних участников UX-01, минимум 4/5 понимают пользу еды и завершают маршрут; без этого G4 не принимается.
- **Конфликты времени:** все таймеры (рост 72 часа, эвакуация 7 дней) используют **одни игровые часы A1**; масштаб времени — отдельная балансная настройка.
- **Неподтверждённые числа:** вероятность лута, XP по уровню и скорость персонажа — [П], не цитировать как правило автора. Пример из первой книги: картофель — 72 часа, +12 часов до порчи; погреб — 10 тонн.
- **Масштаб эвакуации:** 1000 человек хранить агрегированно. Не спавнить 1000 `CharacterBody2D`.
- **Права на игру:** до публичного релиза проверить лицензию на адаптацию и ассеты, возрастные и этические ограничения. Документация сама по себе не предоставляет разрешения.
- **Решить на G0:** 16×16 или 32×32, управление/бой в реальном времени, коэффициент игрового времени, **ожидание у палатки**, **2 картофелины для первых жителей**, точную версию Godot 4.x, локализацию и процедуру утверждения. QA-ускорение задаётся только через детерминированное продвижение общего GameClock в тестовом режиме; не использовать отдельные локальные часы A3/A4.
