# MyShelter — постоянная локальная Windows-сборка

Статус: **draft / код создан, не установлен на пользовательском Windows, пока нет публикации игрового EXE.**

Модуль реализует вариант 2: одна первоначальная установка Python-лаунчера, затем автоматическая проверка и загрузка **только вручную опубликованных** Windows preview. Откат на предыдущую версию возможен локально. Agent Control Center не требуется.

## Важная граница

- Репозиторий PUBLIC. GitHub Release тоже **публичен**. Не публиковать Windows EXE до проверки прав на графику/контент и одобрения владельца. Для защищённой публикации следует настроить GitHub Environment с именем preview-release и Required Reviewers.
- Автоматическая сборка и релиз требуют установленного на default branch (main) workflow. Этот черновой PR на main содержит **только инструменты и CI**, не переносит в main саму игру. После ревью и слияния такого инструментария можно вручную запустить workflow_dispatch для точного полного SHA отдельной интеграционной ветки A5. До этого **публикация ещё не работает**.
- Успешный экспорт не означает G0/G4 approval или полноценное Windows GUI тестирование.

## Первичная установка

Требуются Windows 10/11, Python 3.12+ и работающий py -3. ОДИН РАЗ сохранить в одну локальную папку два файла из проверенного GitHub source:
Install-MyShelter.ps1 и windows_updater.py.

Открыть PowerShell в папке и выполнить:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-MyShelter.ps1

Будут создана папка %LOCALAPPDATA%\MyShelter, один лаунчер MyShelter.cmd, проверка обновлений UpdateMyShelter.cmd и аварийный RollbackMyShelter.cmd. Также создаётся ярлык на рабочем столе. По умолчанию скрипт пытается зарегистрировать ежедневную проверку через Windows Task Scheduler, не требуя администратора. Для отказа от задачи — параметр -NoScheduledTask.

Первый запуск скачает только уже опубликованную preview-сборку. Если Release ещё нет, установщик всё равно сохранит launcher, но игра не появится до первого опубликованного Windows-пакета. Последующие запуски используют локальный EXE сразу и проверяют обновления в отдельном процессе.

**Откат:** RollbackMyShelter.cmd переключает на предыдущий SHA и приостанавливает автообновления; UpdateMyShelter.cmd --force возобновляет. Сохранения Godot user:// updater не трогает, но обратная совместимость мигрировавших сохранений не гарантируется — нужны отдельные save backup и тесты.

## Создание проверенной preview-сборки в GitHub

1. A5 собирает все необходимые изменения A1–A5 в одну integration ветку и фиксирует source SHA; Linux/Windows/документы, право использовать ассеты и критические P0 QA должны быть проверены.
2. После merge CI/tools PR в main: Actions → MyShelter evergreen Windows preview → Run workflow. Вставить lowercase 40-character source_sha проверенной ветки; publish_preview=false. Создастся только Actions artifact (14 дней), публичного Release не будет.
3. Проверить ZIP, запуск EXE/offline smoke и SHA. В GitHub Settings → Environments настроить preview-release с required reviewers, а также запрет публикации из неразрешённых веток.
4. Только после этого повторить workflow_dispatch с publish_preview=true и тем же SHA. Отдельный publish job с write permissions публикует immutable prerelease myshelter-preview-<source_sha> с ZIP + manifest.json.
5. Локальный updater выбирает только публичные prerelease с полным SHA в теге, проверяет manifest и SHA-256 архива. Никакие произвольные PR или main не устанавливаются сами по себе.

## Как гарантируется сохранение рабочей версии

- Скачивание идёт в cache, затем archive SHA-256 и размер проверяются перед распаковкой.
- ZIP с путями не по разрешённому списку, symlink, traversal, повреждённым EXE или подозрительным размером отвергается.
- Новая версия пишется в immutable versions/<source_sha>, переключение state.json атомарно, предыдущая версия остаётся.
- При ошибке сети, пакета, CI, публикации или распаковки прежний EXE не заменяется.
- Если игра уже запущена, отдельный EXE под новым SHA установится для **следующего запуска**; текущая копия не удаляется.
- Обновлятор требует доверия к GitHub HTTPS/публикатору Release; один SHA-256 в том же непроверенном манифесте не является независимой криптографической подписью. Для публичного продукта позже нужны подписанный manifest/code signing и защита release identity.

## Тесты

Из корня репозитория:

    py -3 -m unittest discover -s tools/delivery -p "test_*.py" -v

Тесты офлайн проверяют URL/manifest, целостность ZIP, откат, повторное применение того же SHA, path traversal и восстановление из повреждённой загрузки. Они не заменяют Windows-пробу установки на пользовательском компьютере.

## Принципиальные ограничения текущей реализации

- Никакая сборка для нового общего integration SHA A1–A5 пока не выпущена, работающие игровые файлы пользователя автоматически не заменяются.
- Для запуска рабочего локального EXE требуется единовременная установка через Install-MyShelter.ps1 на ПК пользователя. Подключённое Obsidian-MCP не может выполнять команды Windows или устанавливать приложения.
- Работающий G0-совместимый SAVE, полный 15–35 минутный Windows GUI и 30-минутный FPS/RAM тест остаются отдельными критериями приёмки.
- Репозиторий содержит сторонние UI-ассеты и материалы по мотивам книги. До PUBLIC релиза нужна проверка лицензий/прав; если сборки нужны приватно до проверки, использовать защищённое хранилище с авторизацией вместо публичных GitHub Releases.
